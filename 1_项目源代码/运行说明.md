# 项目四　区域空气质量监测与污染特征分析　运行说明

## 零、先说最快的跑法

解压后进入 `1_项目源代码` 目录（能看到 `build.sbt` 的那个目录）：

- **Windows**：双击 `run.bat`。脚本会自动设置 Hadoop 环境、检查 Java 与 sbt，然后跑完整流程。
  > 脚本自身的提示是英文，程序（九项指标、环境自检表）的输出仍是中文。这是有意为之：cmd.exe 解析含有中文的批处理文件时会因多字节字符错位，把注释行当成命令执行，报出 `'probe' is not recognized` 这类假错误。因此 `run.bat` 与 `打开大屏.bat` 内部保持纯 ASCII。
- **想先看环境有没有问题**：双击 `run.bat` 后在命令行里执行 `run.bat check`，或者手动执行 `sbt "run check"`，会打印一张自检表。
- **跑完看大屏**：双击 `打开大屏.bat`，浏览器会自动打开。

命令行顺序跑一遍的等价写法：

```
cd 1_项目源代码
sbt "run check"      # 环境自检（可选）
sbt "run metrics"    # 完整流水线
```

首次运行需要从 Maven 仓库下载 Spark 依赖（约 300 MB），视网络情况 3～10 分钟；之后每次约 30～45 秒。

## 一、环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| JDK | **11 / 17 推荐**（11 已实测），8 需完整 JDK 而非 JRE | Spark 3.5 支持 8/11/17 三档；`--add-opens` 参数在 JDK8 下会自动跳过 |
| sbt | 1.9.x | 构建与运行入口，需在 PATH 中 |
| Scala | 2.12.18 | 由 sbt 自动下载，无需单独安装 |
| Spark | 3.5.9 | 由 sbt 依赖解析下载，无需单独安装 |
| Python | 3.x（**非必需**） | 只在 JDK 不可用时，作为 `打开大屏.bat` 起静态服务的最后兜底 |

**唯一需要手工安装的是 JDK 与 sbt**，Scala、Spark 都由 sbt 自动拉取。

### Windows 的 hadoop 原生库：已随工程附带，无需配置

Spark 在 Windows 上写 parquet 依赖 Hadoop 的 `winutils.exe` 与 `hadoop.dll`。这两个文件**已放在工程的 `hadoop/bin/` 下**，并且：

1. `build.sbt` 在启动参数里注入了 `-Dhadoop.home.dir` 与 `-Djava.library.path`，指向该目录；
2. `Config.prepareHadoopEnv()` 在程序启动时再探测一次，作为兜底；
3. `run.bat` 会额外设置 `HADOOP_HOME` 环境变量。

三重保障的结果是：**换到任何一台 Windows 机器上都不需要预先配置 `HADOOP_HOME`，也不需要往 JDK 的 bin 目录里复制 dll。**

> 若用 IntelliJ IDEA 直接运行 `aqi.Main`（不经 sbt），IDEA 不会读取 `build.sbt` 里的 `javaOptions`，此时靠第 2 条兜底，仍可正常运行。

### 关于中文用户名（已内置自动处理）

当 Windows 用户名含中文（如"联想"）时，sbt 的 zinc 编译器会在系统临时目录
`C:\Users\<中文名>\AppData\Local\Temp` 下生成 `compiler-bridge` 组件、在
`C:\Users\<中文名>\.sbt` 下缓存 zinc 组件，中文路径会导致编译报错
`cannot redefine component ... compiler-bridge`。

本工程已通过 **`run.bat`** 自动修复——脚本会把 `java.io.tmpdir` 与
`sbt.global.base` 两个 JVM 参数都指到纯英文路径 `%PUBLIC%` 下：

```
-Djava.io.tmpdir=%PUBLIC%\tmp
-Dsbt.global.base=%PUBLIC%\sbt-global
-Dfile.encoding=UTF-8
```

因此**双击 `run.bat` 即可在中文用户名机器上直接跑，无需任何手工配置**。

| 运行方式 | 中文用户名下是否可直接跑 | 说明 |
|----------|------------------------|------|
| 双击 `run.bat` | ✅ | 脚本自动设好上面两个参数，推荐 |
| 命令行 `sbt run` | ⚠️ | 需先手工设 SBT_OPTS（见下），否则会报 compiler-bridge 错误 |
| IntelliJ IDEA 运行 | ⚠️ | 需在 IDEA 的 sbt 设置里补上两个参数（见下） |

> 关键点：**`java.io.tmpdir` 与 `sbt.global.base` 两个参数缺一不可**。只设其中
> 一个仍会报 `cannot redefine component`——zinc 编译器的临时目录读的是
> `java.io.tmpdir`，而它的组件缓存读的是 `sbt.global.base`，两者都含中文路径时
> 都会出错。经实测，这两个参数**必须通过 `SBT_OPTS` 环境变量（或 run.bat）传入**，
> 写成工程根目录的 `.jvmopts` 文件不会在 sbt bootstrap 阶段生效。

> 命令行手动运行前，先执行（或写进你的环境变量）：
> ```
> set SBT_OPTS=-Djava.io.tmpdir=C:/Users/Public/tmp -Dsbt.global.base=C:/Users/Public/sbt-global -Dfile.encoding=UTF-8
> ```
>
> IDEA 用户备注：IDEA 不读取 run.bat。请在 Settings → Build Tools → sbt →
> JVM 参数里补上 `-Djava.io.tmpdir=C:/Users/Public/tmp -Dsbt.global.base=C:/Users/Public/sbt-global`；
> 另外 `Config.prepareHadoopEnv()` 会在运行时兜底 hadoop 原生库。

本项目已在含中文目录名的路径下实测通过（解压后进入 `1_项目源代码` 目录直接运行，
结果与原始运行逐字段一致）。

## 二、运行步骤

### 1. 环境自检（建议第一次先跑）

```
sbt "run check"
```

输出一张表，逐项告知操作系统、Java 版本、CPU 核数、`hadoop.home.dir`、`winutils.exe`、`hadoop.dll`、原始数据、输出目录可写性是否正常。这一段不创建 SparkSession，所以环境不完整时也能正常打印，便于定位问题。

### 2. 数据探查（第一章输出，只读统计，不改原始数据）

```
sbt "run probe"
```

### 3. 单独查看清洗过程（第二章输出）

```
sbt "run clean"
```

### 4. 完整流水线（默认阶段，产出 `cleaned/` 与 `output/`）

```
sbt "run metrics"
```

或直接 `sbt run`。

### 5. 打开可视化大屏

**不要双击 `dashboard/index.html`** —— 页面用 `fetch` 读取 `output/*.json`，`file://` 协议下会被浏览器同源策略拦截，表现为白屏。

Windows 双击 `打开大屏.bat` 即可。脚本会按下面的顺序挑一种能用的方式起服务，**不需要额外安装 Python**：

| 顺序 | 依赖 | 做法 |
|------|------|------|
| 1 | JDK 11+ | `java dashboard\Server.java 8080` 单文件源码模式，直接跑，不编译、不产生任何中间文件 |
| 2 | JDK 8 | `javac` 把 `dashboard/Server.java` 编译到 `dashboard/.build`，再 `java -cp` 运行 |
| 3 | Python 3 | 退化为 `python -m http.server 8080` |

因为跑 Spark 本身就必须装 JDK，前两条基本总有一条可用。脚本先试 8080，被占用则自动换 8081。

手动方式（任选其一，都在 `1_项目源代码` 目录下执行）：

```
java dashboard\Server.java 8080
python -m http.server 8080
```

浏览器访问 `http://127.0.0.1:8080/dashboard/index.html`；直接访问 `http://127.0.0.1:8080/` 会自动跳转到该页。页面按 1920×1080 排版，会按窗口大小**自动等比缩放**，1366×768 的笔记本也能一屏看全（留少量黑边），不需要滚动；按 F11 全屏可获得最大显示面积。

## 四、目录结构

```
build.sbt                       构建配置（含 hadoop 路径注入）
run.bat                         一键运行（Windows）
打开大屏.bat                    一键起服务并打开大屏
hadoop/bin/                     winutils.exe、hadoop.dll（Windows 必需，已附带）

  Config / Model / TimeUtil     ── 配置（含环境自愈）、领域模型、工具
  Reader / Probe / Report       ── 读取层、探查层、展示层
  Cleaner                       ── 清洗层（八步流水线）
  Metrics                       ── 指标层（九项指标）
  Json / Writer                 ── 输出层（序列化与落盘）
  Main                          ── 入口，调度 check / probe / clean / metrics
cleaned/                        清洗后 parquet 明细（4 个数据集）
output/                         11 个指标 JSON
dashboard/                      可视化大屏（ECharts 本地副本，离线可用）
  Server.java                   零依赖静态服务（JDK 自带 HttpServer，替代 Python）
```

## 五、常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| `HADOOP_HOME and hadoop.home.dir are unset` | 启动时找不到 hadoop 目录 | 确认工程根目录下 `hadoop/bin/winutils.exe` 存在；用 `run.bat` 启动；或先跑 `sbt "run check"` 看自检表 |
| `NativeIO$Windows.access0` 报错 | `hadoop.dll` 不在 `java.library.path` 上 | 已由 `build.sbt` 注入并附带 dll；若仍出现，用 `run.bat` 启动 |
| `No main class detected` | 在当前目录找不到 `build.sbt`，sbt 把该目录当成了空工程 | `cd` 到 `build.sbt` 所在目录再运行，注意跨盘符要用 `cd /d` |
| `'probe' is not recognized` / `'清洗' is not recognized` | 批处理文件含中文导致 cmd 解析错位 | 本包的 `run.bat` 已改为纯 ASCII，不会出现；自行改写脚本时请勿在 `.bat` 内写中文 |
| `java9-rt-ext ... rt.jar` 报 NoSuchFileException | 用户名含中文，sbt 缓存路径编码错乱 | `run.bat` 已把 `java.io.tmpdir` 与 `sbt.global.base` 指向 `%PUBLIC%` 下的纯英文路径；手动运行前先设 `SBT_OPTS`（见上文"关于中文用户名"一节） |
| `Neither build.sbt nor a 'project' directory` | 同上，在错误目录运行了 sbt | 同上 |
| 大屏白屏并提示"数据读取失败" | 用 `file://` 直接打开了 HTML | 改用 HTTP 服务访问（步骤 5） |
| 双击 `打开大屏.bat` 报 `'python' 不是内部或外部命令` | 该机没有 Python | 正常现象，脚本会自动改用 JDK 起服务；若连 JDK 也没有，装一个 JDK 11+ 即可 |
| 控制台大量 illegal reflective access 告警 | JDK 11 模块封装限制 | `build.sbt` 已配 `--add-opens`，不影响结果 |
| 报 `Unrecognized option: --add-opens` 且 JVM 退出 | 用的是 JDK 8 | 旧版 build.sbt 无条件注入所致；新版已按 JDK 版本自动跳过，直接更新源码包即可 |
| 中文乱码 | 控制台编码不是 UTF-8 | 已设 `-Dfile.encoding=UTF-8`；必要时先执行 `chcp 65001` |
| 首次运行很慢 | 从网络下载 Spark 依赖 | 正常现象，后续约 30～45 秒 |
| parquet 写入失败但 JSON 正常 | 极端情况下 Hadoop 原生库不可用 | 程序已做降级：九项指标与 JSON 照常产出，大屏不受影响 |
